# 2026-10-18 코드 중간 점검

`Assets/Scripts`와 `Assets/Editor`의 던전 생성·층 이동·AI·풀·입력·표시·UI·창고·저장 및 제작·출시 검사 경로를 검토했다. 기능을 새로 설계하기보다 확인된 오류 위험, 반복 연산, 중복 규칙을 수정했다.

## 오류와 안전성

| 확인한 문제 | 수정 |
| --- | --- |
| 가까운 바닥을 찾는 반경이 가로 길이에만 제한되어 4×64 같은 맵의 먼 방을 찾지 못함 | 가로·세로 중 긴 길이까지 탐색하고 이미 검사한 내부 영역은 건너뜀 |
| 적의 저장 스냅샷이 현재 개체의 능력치를 직접 참조함 | `EnemyAgent.Capture()`에서 능력치와 이전 드롭 목록을 독립적으로 복사 |
| 저장 수집 중 반환할 현재 층 목록을 내부 탐험에도 연결함 | 먼저 탐험 사본을 만든 뒤 그 사본에만 현재 층 상태를 채워 호출자와 내부 상태를 분리 |

| 수동 던전 생성과 자동 후보 채택의 신규 파일 경로 검사가 다름 | `TryNewAssetPath`로 통합하고 Assets 밖으로 벗어나는 경로, 기존 파일 덮어쓰기, 다른 확장자, 없는 부모 폴더를 거부 |

| 가방 재료 획득 경로의 출시 검사가 층별 스폰 대신 남아 있는 단층 설정을 읽음 | 실제 사용하는 스폰 규칙을 공통 열거 메서드로 제공하고 등록·입장·출시 검사에서 공유 |
| 보관 중인 3D 실험 경로에서 없는 모델·애니메이션을 참조할 수 있음 | 표시 방향의 기본값과 공격·걷기 클립의 존재 여부 확인 |

## 반복 연산과 자원

- 층의 입구에서 도달할 수 있는 스폰 후보와 입구 거리는 한 번만 계산한다. 스폰 사이에 실행되는 AI 탐색이 이 캐시를 덮어쓰지 않는다.
- 후보마다 모든 기존 배치와의 거리를 다시 계산하는 대신, 새로 추가된 위치만 최소 거리 캐시에 반영한다. 바닥 수 F, 배치 수 N에서 누적 거리 갱신은 일반적인 순차 배치에 대해 O(F×N)이다. 목록이 줄거나 기존 위치가 바뀌면 다시 계산한다. 거리 비교에는 제곱 거리를 사용하고 후보 리스트 용량을 재사용한다.
- 탐험 저장용 깊은 복사에서 JSON 문자열 생성과 파싱을 제거했다. 도면·스폰 ID·적 능력치·시체 전리품·해체 세션·탐색 기록을 형식별 `Copy()`로 독립 복사한다. 파일을 저장하는 JSON 형식과 암호화 방식은 유지한다.
- 창고 전리품 복사에서 불필요한 전리품 복원·재생성을 제거했다. 구 저장의 종류 ID와 도형 정규화는 불러올 때 수행한다.
- 가방 확장 화면의 재료 가격 조회는 창고 변경 시 가격순 목록을 갱신하며, UI 호출마다 깊은 복사와 정렬을 하지 않는다. 외부에 제공하는 창고 목록은 계속 독립 복사본이다.
- 스프라이트 캐시를 초기화할 때 직접 만든 Sprite와 텍스처 사본도 해제한다. Resources 원본은 해제 대상에 포함하지 않는다.
- 음량 변경 이벤트와 중복되던 `GameAudio.Update()`의 설정 참조 비교를 제거했다.

## 제거 및 유지

호출과 씬·프리팹 참조를 확인한 뒤 빈 `DungeonDemoBootstrap`, `DungeonTestVerticalSlice` 파일과 `.meta`, 사용하지 않는 `DungeonVisionFog` 식별 클래스·검색·옛 크기 설정을 제거했다. `GetNextPathPoint`, `NotifyPlayerCaught`, `ContainsShape`의 미사용 메서드도 제거했다.

기존 씬에서 참조하는 상호작용·해체 컴포넌트, ID가 없는 구 저장의 복원 경로, 설정으로 선택할 수 있는 Blender 3D 표시 경로는 유지한다. 실제로 선택할 수 있거나 직렬화 참조가 남은 코드는 현재 기본 설정에서 실행되지 않는다는 이유만으로 지우지 않았다.

`Assets/MidtermProfiling/`, 관련 `.meta`·`.asmdef`, 활성화 방식, 기존 측정 결과는 변경하지 않았다. 던전 도면·카탈로그·프리팹·씬과 사용자의 실제 저장 파일도 수정하지 않았다.

## 검증

`Tools/Validate-GameFlow.ps1 -CaptureScreens`로 별도 프로젝트·저장 경로에서 Unity 실행 검사, Windows 비개발 Mono 빌드, 재실행 복원 및 화면 캡처를 검사한다. 회귀 검사에는 다음을 추가했다.

- 4×64 / 64×4 맵에서 먼 방의 바닥 탐색
- 밀집 배치의 유일한 빈 칸, 기존 위치 교체, 배치 목록 초기화
- 스냅샷의 능력치를 편집해도 실제 적이 바뀌지 않는지 확인
- 도면·스폰 목록·전리품 도형·해체 세션·탐색 기록의 복사 독립성
- 첫 반환 이후 추가된 컴포넌트의 풀 초기화
- 재료 가격 조회의 캐시 갱신과 예열 후 반복 호출의 관리 메모리 무할당
- 제작 에셋 경로의 공통 검증과 실제 층별 드롭 경로 검사

기존 벽 충돌 검사가 얇은 경계 벽만 가정하던 부분도 제작 툴의 전체 벽 칸을 포함하도록 수정했다. 벽 종류별 실제 크기와 외부에서 쏜 Raycast가 해당 벽의 경계에 닿는지를 검사한다.

최종 코드의 실행 결과:

| 실행 환경 | 통과한 검사 |
| --- | ---: |
| Unity 실행 | 579 |
| Windows 비개발 Mono 플레이어 | 519 |
| 별도 프로세스 재실행·저장 복원 | 12 |

화면 캡처 생성도 완료했으며 던전·가방 확장 화면을 확인했다. 검사 횟수는 선택된 던전의 벽·스폰 수 등에 따라 달라진다. 예열 후 재료 가격 조회 8회에서 해당 스레드의 추가 관리 메모리 할당은 0바이트였다. 검증 프로젝트의 임포트 중 기존 Unity 검색 인덱서의 `ArgumentOutOfRangeException`이 기록됐지만, 이번 게임 코드의 컴파일 오류·검사 실패는 남지 않았다.

FPS 개선 비율, 모든 코드의 무할당, 최대 콘텐츠에서의 장시간 안정성을 입증한 결과는 아니다. 다음 측정에서는 목표 스폰 수와 실제 아트를 사용해 첫 입장·반복 입장·저장·AI 추적의 CPU 시간, GC.Alloc, 메모리 보관량을 기존 프로파일링 도구로 확인해야 한다.
