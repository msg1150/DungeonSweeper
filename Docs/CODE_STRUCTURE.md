# 게임 코드 구조

2026-10-22 기준. 실제 실행 코드를 `Assets/Scripts/Runtime`으로 분류하고 `Demo` 폴더·HUD 타입·화면 문구를 정리했습니다. 게임은 개발 중이며 이 구조 정리가 최종 콘텐츠나 출시 검증 완료를 뜻하지는 않습니다.

## 기능별 위치

| 폴더 (`Assets/Scripts/Runtime/` 기준) | 역할 |
| --- | --- |
| `Core` | 새 게임·저장 불러오기·씬 이동의 `GameSession`, 설정, 공통 수치 검증 |
| `Persistence` | 저장 DTO, 암호화, 슬롯 파일 읽기·원자적 교체와 백업 |
| `Dungeon/Data` | 던전 카탈로그·층 도면·난이도·시야·탐험 스냅샷 |
| `Dungeon/Generation` | 제작 도구가 호출하는 데이터 기반 맵 생성 |
| `Dungeon/World` | 현재 층의 지형·충돌체·탐색과 스폰 좌표 구성 |
| `Dungeon/Runtime` | 탐험 진행 조정, 층 이동·은신·회수·저장, 배우 풀 |
| `Dungeon/Compatibility` | 구 저장과 초기 도면 변환에 필요한 예전 평면의 독립적인 복사본 |
| `Actors/Player`, `Actors/Monsters` | 플레이어 이동·체력, 몬스터 설정·순찰·추격·공격 |
| `Recovery` | 시체 프리팹, 해체 난이도·진행과 런별 시체 상태 |
| `Inventory` | 전리품 정의, 점유 도형, 가방 배치, 드롭 보정 |
| `Town` | 의뢰·보급·골드·창고·판매 잠금·가방 확장 |
| `Presentation` | 아트 캐시, 애니메이션, 2.5D 배우·카메라·배경·시야 표시 |
| `UI/Common`, `UI/Menus`, `UI/Dungeon`, `UI/Town` | 공용 테마, 메뉴·옵션·슬롯, 탐험 HUD, 마을 거래 화면 |
| `Audio` | 씬별 음악과 UI 효과음·옵션 음량 연결 |
| `Diagnostics` | 기존 에디터 전용 몬스터 인식 범위 표시 |

`Assets/Editor`는 `Dungeons`, `Inspectors`, `Presentation`, `Configuration`, `Build`로 나눴습니다. 에디터 API는 기존 Editor 컴파일 경계를 사용하고 런타임과 함께 배포되지 않습니다. 이번에는 어셈블리·네임스페이스를 바꾸지 않아 기존 직렬화 타입과 외부 참조가 유지됩니다.

`ThreeDWorldView` 계열 이름은 실제 입체 지형과 선택 가능한 표시 설정을 의미합니다. 현재 사용하는 스프라이트 배우 2.5D 경로와 보관 중인 Blender 모델 경로를 임의로 제거하지 않았습니다.

## 조정자와 표시 계층

- `GameSession`: 탐험·마을을 오가는 세션 상태와 저장 요청을 조정합니다.
- `GameShell.cs`: 입력 차단·일시정지·화면 전환·정상 종료 흐름을 처리합니다. `GameShell.Views.cs`는 메뉴·옵션·저장 슬롯의 표시와 버튼 연결입니다.
- `DungeonRunController.cs`: 현재 층 구성·참조·갱신·종료를 맡습니다. 같은 타입의 partial 파일인 `Interactions`, `Hiding`, `Floors`, `Persistence`에 작업·은신·계단·저장 처리를 나눴습니다. 별도 컴포넌트나 이중 상태 저장소를 추가하지 않았습니다.
- `DungeonHud.cs`: 탐험 HUD·지도·상황 안내를 그립니다. `DungeonHud.LootPlacement.cs`는 카드·가방 표시와 드래그·회전 UI입니다. 게임 규칙 변경은 런 컨트롤러에 요청합니다.
- `LootDefinition`, `DismantleDifficulty`, `DismantleSession`, `CorpseRunData`는 각각 전리품·해체 규칙·진행·시체 상태 파일에 있습니다.

## 씬과 테스트

실제 빌드 흐름은 기존 **MainMenu → Town → Dungeon**입니다. 테스트 씬은 GUID를 유지해 `Assets/Tests/Scenes/DungeonSandbox.unity`로 옮겼으며 빌드 씬 목록에는 넣지 않습니다. 제작 도구와 샌드박스는 에디터에서 실제 런타임 코드를 그대로 사용합니다.

`Tests/ValidationContentFixture.cs`는 격리 검사용 샘플 던전을 준비합니다. 실제 제작 서비스에 검사용 던전을 자동 등록하는 메서드를 두지 않습니다. 테스트 코드 원본은 Assets 밖의 `Tests`에 있고 검증할 때만 `.utmp/UnityValidation/Assets/Validation/{Runtime,Editor}`로 복사됩니다.

`Tools/Validate-GameFlow.ps1 -EditorOnly`는 Play 모드 없이 컴파일·기존 에디터 검사와 출시 설정 사전 검사를 수행합니다. 이동으로 남은 오래된 검증용 코드·폴더 메타는 격리된 Scripts/Editor 복사본에서만 제거합니다. 실제 소스·저장·프로파일링 결과는 정리 대상으로 삼지 않습니다.

## 저장과 참조 호환성

- 기존 스크립트 74개의 `.meta`를 함께 옮겨 GUID를 보존했습니다. 기존 씬·프리팹·설정 에셋은 새 위치의 같은 스크립트를 참조합니다.
- `DungeonDemoHud`를 `DungeonHud`로 바꾸고 GUID는 유지했습니다. Inspector에서 컴포넌트를 다시 붙일 필요가 없습니다.
- 저장 버전·암호화·슬롯 경로·전리품 ID·던전 ID는 유지합니다. 사용자 저장 파일을 삭제하거나 마이그레이션 목적으로 덮어쓰지 않았습니다.
- 구 평면 조회는 `LegacyDungeonLayouts`를 사용합니다. 템플릿은 수정 가능한 독립 복사본으로 반환하고 배치 가능 수는 캐시합니다. 에셋 검사·구 저장 변환이 실행 중인 층이나 스폰 후보를 바꾸지 않습니다.
- 프로파일링 폴더 12개 파일의 변경 전후 해시가 같습니다. 기존 조건·asmdef·메뉴·활성화 방식도 유지합니다.

## 이번 안전성·성능 보완

- 가방 복원은 모든 항목·점유 위치를 임시 가방에서 검사한 후 한 번에 반영합니다. 실패하면 기존 아이템 객체·배치·합계가 유지됩니다.
- 해체 진행 복원은 저장된 창을 사용하며 난수를 소비하지 않습니다. 새 해체 시작에서만 창을 무작위로 정합니다.
- 창고 총수량과 종류별 재료 수량은 변경 시 집계해 조회합니다. 기존 가격별 정렬 캐시와 UI revision도 유지합니다.
- 메뉴 버튼의 입력용 GUIContent를 재사용합니다.
- 유한 수치 검증은 `ValueValidation`로 모아 가방·저장·시야·해체가 몬스터 정의의 유틸리티 메서드에 의존하지 않게 했습니다.

구조 변경·초기 마을 상태·가방 복원 원자성·해체 난수·대량 창고 수량·예전 평면 보존·실행 중 캐시 독립성·출시 설정을 포함해 에디터 검사 **186개**를 통과했습니다. 실제 플레이·장시간 사용·FPS/Draw Calls 측정은 이번에 수행하지 않았습니다.

## 사용자가 확인할 순서

1. `MainMenu`에서 새 게임 → 마을 시설 → 던전 선택으로 입장합니다.
2. 걷기·대시, 몬스터 추격·소음 반응·은신 진입과 종료를 확인합니다.
3. 시체 해체·회전·가방 드래그·포기 후 계단을 왕복합니다.
4. 던전에서 수동 저장 후 이어하기로 가방·진행·현재 층이 복원되는지 확인합니다.
5. 귀환 후 창고 수량·종류별 재료 수량·판매·판매 잠금·가방 확장·의뢰 제출을 확인합니다.
6. 옵션·일시정지·메인 복귀·정상 종료를 확인합니다. 이전 저장은 별도 보관한 뒤 기존 슬롯 이어하기도 확인해 주세요.
