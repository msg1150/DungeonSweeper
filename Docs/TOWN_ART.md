# 마을 원화와 배치

2026-10-26 적용. 바탕화면 `GameAsset/DungeonSweeper_Town_v1`의 배경 1장과 투명 시설 PNG 4장을 `Assets/Art/Town`에 원본 그대로 복사했습니다. 합성 미리보기는 배치 참고용이며 게임 화면에는 별도 배경과 시설을 표시합니다.

| 시설 | 원화 기준 발판 위치 (좌측 상단 원점) | 화면 폭 대비 실제 그림 폭 |
| --- | --- | --- |
| 길드 | (0.273, 0.448) | 20% |
| 거래소 | (0.531, 0.29) | 16% |
| 창고 | (0.381, 0.652) | 14% |
| 던전 포탈 | (0.746, 0.493) | 13% |

첫 배치는 `layout-reference.json`을 사용했고, 이후 사용자가 표시한 같은 색 원의 이동량을 반영했습니다. 마지막 미세 조정에서는 길드·창고를 오른쪽 위로, 포탈을 왼쪽 위로 옮기고 거래소 위치는 유지했습니다. 거래소는 지붕이 잘리지 않도록 위쪽 경계를 확보했습니다. 각 PNG의 원래 비율과 크기는 유지합니다.

## 조정 위치

`Assets/Resources/TownPresentation.asset`을 선택합니다.

- **Background**: 건물이 없는 배경 Sprite입니다.
- **Feet Anchor**: 시설 발판의 정규화 좌표입니다. (0,0)은 배경 왼쪽 위, (1,1)은 오른쪽 아래입니다.
- **Visible Width**: 배경 폭 대비 시설 그림 폭입니다. **Image Width Fraction**은 원본 PNG에서 투명 여백을 제외한 그림 폭의 비율이므로 에셋을 교체할 때 함께 맞추세요.
- **Footprint Base Height**: 알파가 있는 그림 중 아래에서부터 충돌로 사용할 높이 비율입니다. 기본 25%이며 지붕과 처마는 통행을 막지 않습니다.
- **Footprint Alpha Threshold**: 충돌에 포함할 최소 알파값입니다. 기본 0.5로 흐린 접지 그림자를 제외합니다.
- **Footprint Outline**: 생성해 저장한 다각형입니다. 직접 점을 늘리기보다 **PNG 알파 기반 충돌 재생성** 버튼을 사용하세요. Sprite·원본 픽셀·위 두 설정을 바꿨다면 다시 생성해야 합니다. 위치나 그림 크기만 바꾸면 재생성 없이 같은 윤곽이 변환됩니다.
- **Player Spawn**: 새 게임에서 사용할 광장 위치입니다.
- **Walkable Outline**: 통행 가능한 육지의 외곽선입니다. 마지막 점은 첫 점에 자동으로 연결됩니다. 강가 진입을 막고 아래쪽 다리는 걸어갈 수 있게 구성했습니다.

시설의 **Object Name**은 길드 `Salvager Guild`, 거래소 `Supply Shop`, 창고 `Town Warehouse`, 포탈 `Dungeon Entrance`를 유지하세요. 기존 시설 UI가 같은 루트를 참조합니다.

Town 씬을 다시 열면 기존 에디터 미리보기에서 배치를 적용합니다. Play 시작 시에는 현재 에셋을 다시 읽어 적용하며 씬 파일을 별도로 저장할 필요는 없습니다. 설정이 유효하지 않으면 Inspector와 출시 사전 검사에서 알립니다.

## 알파 기반 충돌

`TownFootprintBaker`가 에디터에서 PNG를 읽고, 설정한 알파값 이상의 그림 영역 중 밑부분만 선택합니다. 각 픽셀 행의 왼쪽·오른쪽 외곽을 잇고 Ramer–Douglas–Peucker로 약 2픽셀 이내의 작은 굴곡을 단순화합니다. 꼭짓점은 최대 256개이며 복잡하면 단순화 허용치를 늘립니다. 내부 구멍과 같은 행에서 분리된 부분 사이의 틈은 채웁니다. 따라서 전체 그림을 매 픽셀 그대로 재현하는 충돌은 아닙니다.

생성 결과만 에셋에 저장하고 실제 접촉은 `PolygonCollider2D`로 처리합니다. 이전 사각 충돌은 비활성화해 중복으로 가로막지 않습니다. 2.5D 카메라의 기울기를 반영해 밑동 외곽을 논리 지면에 투영하므로 단순히 Sprite 전체의 Physics Shape를 쓰는 것과 다릅니다. 저장 위치의 유효성 검사도 같은 다각형을 사용합니다.

Unity에도 [Sprite Editor의 Custom Physics Shape와 Polygon Collider](https://docs.unity.com/en-us/engine/6000.0/manual/unity2d/sprite/create-collision-geometry)로 알파 외곽을 생성하는 기능이 있습니다. 현재 방식은 우리 마을의 밑동 선택과 2.5D 좌표 변환을 추가한 에디터 생성 도구입니다. 플레이 중에는 픽셀을 읽거나 윤곽선을 재생성하지 않습니다.

## 표시와 저장 좌표

기존 2.5D 방식으로 배경은 지면에, 건물은 수직 스프라이트로 표시합니다. 발판 피벗은 임포트 시 지정해 건물의 GPU 알파 읽기를 생략합니다. 원화에 포함된 접지 그림자를 사용하므로 별도의 건물 그림자를 중복 표시하지 않습니다.

원화 비율 약 1.94:1을 유지하며 화면 비율이 달라지면 카메라 표시 영역을 맞춥니다. 가장자리에 여백이 생길 수 있지만 시설·플레이어·충돌의 월드 좌표는 화면 크기에 따라 이동하지 않습니다. 던전 카메라는 기존 전체 화면 구성을 유지합니다.

이전 저장의 마을 좌표가 새 건물이나 물가에 걸리면 광장의 안전한 위치로 보정합니다. 통행 가능한 기존 좌표는 그대로 사용하며 사용자 저장 파일을 삭제하지 않습니다.

## 확인 범위

격리된 Unity 에디터에서 다음 명령으로 **288개 검사**를 통과했습니다. 컴파일 오류·경고와 검사 예외는 없었으며 Play 모드와 게임 빌드는 실행하지 않았습니다.

```powershell
./Tools/Validate-GameFlow.ps1 -EditorOnly -ValidationWorkspace '.utmp/q'
```

실제 임포트된 Sprite 참조·발판 피벗, 2.5D 카메라 투영, 화면 비율 대응, 시설 표시와 충돌 좌표, 이전 저장 위치 보정, 닫힌 외곽선과 재적용 시 시설 중복 방지를 검사했습니다. 알파 합성 마스크로 지붕·흐린 그림자 제외와 투명 이미지 거부를 확인했고 실제 PolygonCollider2D의 경로가 저장 위치 검사와 일치하는지도 확인했습니다. 화면의 최종 인상과 이동 감각은 수동 확인 대상입니다.

1. MainMenu에서 새 게임으로 들어가 길드 왼쪽·거래소 상단 중앙·창고 왼쪽 아래·포탈 오른쪽 배치를 확인합니다.
2. 각 시설의 문 앞으로 이동해 E로 해당 화면이 열리는지 확인합니다.
3. 건물 밑동과 강가 통과가 차단되고 광장·아래 다리에서는 이동할 수 있는지 확인합니다.
4. 던전 입장 후 귀환하고, 마을에서 저장·이어하기도 확인합니다.
5. 창 크기와 해상도를 바꿨을 때 건물과 상호작용 지점이 어긋나지 않는지 확인합니다.
