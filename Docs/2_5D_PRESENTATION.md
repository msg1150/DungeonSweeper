# 2.5D 표시

2026-10-16. 기본 표시를 원래 일러스트 배우와 입체 공간을 함께 사용하는 2.5D로 변경했다. MainMenu에서 새 게임 또는 이어하기로 진입한다. 씬을 다시 로드하거나 Play를 재시작하면 반영된다.

## 화면

- 고양이·몬스터·시체·게이트는 기존 스프라이트를 사용한다. 이동, 대시 착지·페이드, 공격 방향과 시트 경계 보정도 그대로 실행한다.
- 마을은 기존 밝은 배경 그림을 지면으로 배치하고 시설과 고양이를 별도의 카메라 방향 스프라이트로 세운다. 앞뒤 위치에 따라 가림 순서가 바뀌고 발밑에 부드러운 접촉 그림자를 둔다.
- 던전은 기존 그림 텍스처를 적용한 바닥·두께 있는 벽·벽 윗면을 사용한다. 앞쪽 벽은 낮고, 게이트 주변 조명과 어두운 시야 효과를 유지한다.
- 카메라는 58도 정사영이다. 가까운 물체가 과하게 커지는 원근 왜곡 없이 깊이를 표현한다. 스프라이트는 카메라를 향해 그림 비율을 유지한다.

## 구현과 편집

`Assets/Resources/ThreeDPresentation.asset`의 Use Sprite Actors가 기본으로 켜져 있다. Sprite Camera Elevation, Dungeon View Size, Town View Size에서 각도와 화면 범위를 조절한다. 기존 에셋·저장 연결을 유지하기 위해 설정과 월드 클래스 이름은 변경하지 않았다.

`SpriteDepthView`는 논리 객체의 SpriteRenderer를 재사용해 표시 사본에 자세·뒤집기·색·알파를 전달한다. 첫 자세의 실제 발 위치를 한 번 계산하고 이후 프레임에는 위치가 흔들리지 않게 유지한다. 플레이어 대시의 이전 자세 사본도 같은 방식으로 페이드한다. 사본의 정렬은 XY 논리 좌표의 Y를 따른다.

논리 좌표와 Rigidbody2D는 기존 XY 그대로이고 표시만 XZ로 변환한다. 저장, 상호작용 거리, AI 경로, 공격 판정에는 새 좌표 형식이 없다. 마을 시설 발판과 외곽에는 논리 충돌체를 둔다. 빌보드 자체에는 충돌체를 추가하지 않는다.

정사영 시야 셰이더는 화면 네 모서리의 광선과 지면 교차점으로 시야 거리를 구한다. 원근 카메라에서 사용하던 단일 광선 시작점을 정사영에 적용하지 않는다.

몬스터·시체의 표시 사본도 풀 아래에서 보관하고 재입장 시 같은 객체를 재사용한다. 새 장면에 들어오면 장면 소유 접촉 그림자를 다시 연결한다. 장면 그림자 텍스처·스프라이트·합친 던전 메시·런타임 재질은 장면 종료 시 해제한다. 공용 스프라이트 재질은 Resources 에셋이며 빌드에서 셰이더 참조를 유지한다.

Blender 원본과 3D 프리팹은 삭제하지 않았다. Use Sprite Actors를 끄면 보관한 3D 모델로 비교할 수 있다. Use 3D를 끄면 평면 2D 표시다. 프로파일링 도구와 측정 결과는 변경하지 않았다.

## 검증

`Tools/Validate-GameFlow.ps1 -CaptureScreens`로 격리 프로젝트의 게임 흐름, 일반 Windows 빌드, 별도 프로세스 저장 복원을 검사한다. 원래 스프라이트 자세·대시·공격 갤러리 검사와 함께 정사영 카메라, 표시 좌표 정합, 빌드 셰이더, 던전 벽, 정사영 시야, 장면 이동 시 표시 객체 재사용을 확인한다. 실제 화면은 `.utmp/UnityValidation/release-town.png`, `release-dungeon.png`에 생성된다.

최종 검증: Unity 게임 흐름 485개, 일반 Windows 빌드 443개, 별도 프로세스 저장 복원 10개 통과. 16장 화면을 캡처하고 마을·던전·배치 화면을 시각 검토했다. 현재 화면 사본은 `Docs/Images/2.5D/`에 보관한다. 검사 개수는 무작위 배치에서 재사용한 배우 수에 따라 달라질 수 있다.
