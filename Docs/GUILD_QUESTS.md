# 회수 길드 의뢰

2026-10-26 기준. 길드에서 의뢰를 선택해 수락하고 창고 재료를 제출합니다. 조건과 보상은 에셋으로 관리하며 코드를 고치지 않고 의뢰를 추가할 수 있습니다.

## 기본 의뢰

`Assets/Resources/QuestCatalog.asset`에 다음 4개를 연결했습니다. 초기 밸런스이므로 각 에셋에서 수정하세요.

| 의뢰 | 제출 재료 | 보상 | 반복 |
| --- | --- | ---: | --- |
| 고블린 장비 수거 | 낡은 단검 1개 | 120G | 가능 |
| 슬라임 연구 재료 | 슬라임 점액 5개 + 슬라임 핵 1개 | 220G | 가능 |
| 오크 잔해 정리 | 오크 엄니 2개 + 두꺼운 가죽 1개 | 300G | 가능 |
| 길드 첫 납품 | 고블린 가죽 3개 | 180G | 한 번 |

## 새 의뢰 만들기

1. Project 창의 `Assets/Resources/Quests`에서 **Create → Dungeon Sweeper → Quests → Quest Definition**을 선택합니다.
2. **Quest Id**에 고유 ID를 지정합니다. 예: `quest.goblin-supplies`. 저장과 완료 기록의 식별자이므로 배포 후에는 바꾸지 마세요.
3. **Display Name / Description**에 이름과 설명을 작성합니다.
4. **Requirements**에 필요한 종류를 한 행씩 추가합니다. 같은 종류 ID를 중복 등록하지 마세요.
5. 각 행의 **Kind Id / Display Name / Quantity**에 전리품 종류 ID·표시 이름·수량을 넣습니다. 기존 시체 프리팹 `Loot`의 Kind Id와 같은 값을 사용합니다.
6. **Gold Reward / Repeatable**을 설정하고 `QuestCatalog.asset`의 **Quests** 배열에 연결합니다. 배열 순서가 길드 목록 순서이며, 진행 중인 의뢰는 맨 위에 표시합니다.

기본 종류 ID는 `goblin.dagger`(낡은 단검), `goblin.hide`(고블린 가죽), `slime.gel`(점액), `slime.core`(핵), `orc.horn`(엄니), `orc.hide`(두꺼운 가죽)입니다.

이름과 재료 표시 이름은 각각 120자, 설명은 2000자, 재료는 1~16종, 각 필요 수량은 1~1,000,000개, 카탈로그는 1~512개까지입니다. 잘못된 값과 중복 ID는 Inspector에 표시하고 수락·빌드 검사에서 차단합니다. 빌드 검사에서는 제출 재료가 실제 스폰되는 시체의 드롭 목록에 있고 드롭 확률·수량이 0이 아닌지도 확인합니다.

## 플레이 규칙

- 동시에 진행하는 의뢰는 1개입니다. 길드 목록에 **수락 가능 / 진행 중 / 완료 가능 / 완료**를 표시합니다. 다른 의뢰가 진행 중이면 새 수락을 막습니다.
- 재료 진행도는 **창고 보유량**입니다. 던전 가방의 회수품은 귀환·창고 보관 후 반영됩니다. 필요한 수량보다 많이 보관해도 제출 시 필요한 만큼만 사용합니다.
- 여러 재료가 전부 있어야 제출할 수 있습니다. 같은 종류에서는 판매 가격이 낮은 것부터 사용합니다. 판매 잠금은 의뢰 제출을 막지 않습니다.
- 재료·보상 골드·완료 이력을 함께 반영하고 자동 저장을 요청합니다. 재료 부족이나 골드 초과로 실패하면 어떤 재료도 소비하지 않습니다.
- 한 번만 완료하는 의뢰는 완료 이력을 저장해 다시 수락하지 못하게 합니다. 반복 의뢰는 다시 수락해야 다음 보상을 받을 수 있습니다. 제출 버튼을 연속으로 눌러도 보상은 중복 지급하지 않습니다.
- **의뢰 포기 → 포기 확인**으로 의뢰를 정리할 수 있습니다. 골드·창고 재료를 소비하지 않습니다.
- 기존 사망 규칙을 유지합니다. 사망 시 진행 중 의뢰는 해제하고 이미 완료한 이력과 보관 재료·골드는 유지합니다.
- 새 게임은 진행 중 의뢰와 완료 이력을 초기화합니다.

## 저장 호환성

수락 시 이름·설명·보상·반복 여부·요구 재료를 독립 스냅샷으로 저장합니다. 수락 후 원본 에셋을 수정하거나 카탈로그에서 제거해도 진행 중 의뢰는 원래 조건으로 표시·제출할 수 있습니다. 다음 수락 때 새 조건을 사용합니다.

이전 저장의 무작위 단일 품목 의뢰는 **기존 회수 의뢰**로 표시하며 당시 요구 품목 1개·보상 120G를 이어받습니다. 완료 후 새 목록에서 다른 의뢰를 선택합니다. 저장 컨테이너 버전·암호화·슬롯 경로는 유지하고 마을 데이터에 의뢰 구분 버전·스냅샷·완료 ID 목록을 추가했습니다. Unity가 null 스냅샷을 빈 객체로 복원하는 경우에는 명시적인 수락 플래그로 의뢰 유무를 구분합니다.

## 코드 위치

- `Runtime/Quests`: 의뢰 정의·카탈로그·변경 불가능한 수락 조건
- `Runtime/Town/TownQuestProgress.cs`: 수락·제출·포기·이력과 저장 요청
- `Runtime/Persistence/QuestSaveData.cs`, `LegacyQuestMigration.cs`: 검증·깊은 복사·이전 저장 변환
- `Runtime/UI/Town/TownCommercePanel.Quests.cs`: 길드 목록·선택·진행도·확인 UI
- `Editor/Inspectors/QuestInspectors.cs`: 에셋 편집 안내·검증

## 검증과 직접 확인

에디터 검사 **225개**를 통과했습니다. 의뢰 거래·수락 조건 보존·암호화 메모리 왕복·완료 후 빈 상태 복원·일회성 이력·반복·보상 초과·이전 저장 변환·원본 에셋 제거 후 제출을 포함합니다. 검사에서는 Play 모드와 플레이어 빌드를 실행하지 않았습니다.

별도 성능 실험 복사본과 충돌하지 않게 이번 검사는 새 워크스페이스를 사용했습니다.

```powershell
./Tools/Validate-GameFlow.ps1 -EditorOnly -ValidationWorkspace '.utmp/q'
```

결과는 `.utmp/q/.utmp/UnityValidation/source-cleanup-result.txt`, 로그는 같은 폴더의 `unity-validation.log`에 있습니다. 기존 프로파일링 도구·측정 결과를 삭제하거나 비활성화하지 않습니다. 일반 복제본에서는 기존 `-EditorOnly` 명령도 사용할 수 있습니다.

플레이는 다음 순서로 확인해 주세요.

1. `MainMenu → 새 게임 → 마을 길드 [E]`에서 목록과 각 의뢰의 조건·보상을 확인합니다.
2. 고블린 장비 수거를 수락하고 다른 의뢰의 동시 수락이 막히는지 확인합니다. 단검을 회수해 귀환하면 길드에서 `1/1`과 **완료 가능**을 표시해야 합니다.
3. 제출 시 재료 1개가 줄고 120G가 늘어나는지, 반복 의뢰를 다시 수락할 수 있는지 확인합니다.
4. 슬라임 의뢰에서 한 종류만 모았을 때 제출이 막히고 모든 재료를 모으면 필요한 수량만 소비하는지 확인합니다.
5. 길드 첫 납품을 완료하고 저장·이어하기 후에도 **완료**로 남는지 확인합니다.
6. 진행 중 저장·이어하기, 포기 확인·취소, 사망 후 해제도 확인합니다. 이전 저장에 진행 중 의뢰가 있다면 기존 조건으로 이어지는지도 확인합니다.
