# 던전 제작과 여러 층 탐험

Unity 메뉴 **Dungeon Sweeper → Dungeon Builder**에서 제작 창을 연다. 별도 씬을 만들거나 게임 코드를 수정하지 않고 던전 도면과 층별 스폰 목록을 편집한다.

## 제작 순서

1. **새 던전**을 누르고 Assets 아래에 데이터 에셋을 저장한다. 기본으로 연결된 방과 복도가 있는 첫 층을 만든다. 기존 던전을 편집하려면 상단 에셋 칸이나 시작 목록에서 선택한다.
2. 왼쪽 도구에서 **바닥 / 벽 / 빈 공간**을 선택하고 오른쪽 격자에서 드래그한다. 오른쪽 드래그는 빈 공간으로 지운다. Ctrl+Z로 한 번의 드래그를 취소할 수 있다. 확대 슬라이더와 스크롤로 넓은 도면을 편집한다.
3. **입구 기준**으로 첫 층의 귀환 포탈 위치를 정한다. **층 추가** 후 각 층의 위·아래 계단을 배치한다. 위층과 아래층의 계단 좌표는 서로 달라도 된다. 층 목록의 순서대로 연결된다.
4. 각 층의 **몬스터 / 시체** 목록에 프리팹과 수량을 넣는다. 위치를 도면에 직접 배치하지 않는다. 입장 시 알고리즘이 도달 가능한 바닥에서 위치를 선택하고 입구·계단 칸을 비워 둔다.
5. **검증 → 저장 + 게임에 등록**을 누른다. 도면·스폰 에셋을 저장하고 DungeonCatalog에 던전과 사용 프리팹을 자동 등록한다. 이후 마을 포탈에서 새 탐험을 시작하면 선택 대상에 포함된다.

**선택 던전만 바로 테스트하려면:** MainMenu에서 새 게임으로 마을에 들어간 후, 제작 창에서 원하는 던전을 선택하고 **선택 던전 입장**을 누른다. Play 중에는 도면 편집이 잠긴다. 기존 탐험의 도면은 저장 당시 스냅샷을 사용하므로 변경 확인은 새 탐험에서 한다.

## 층과 탈출 규칙

- 첫 층에만 들어왔던 귀환 포탈이 있다. 깊은 층에서 입구로 탈출하려면 계단을 따라 첫 층까지 올라온다.
- 추가 탈출 포탈은 **던전 전체에 하나**다. `추가 포탈 층`은 0부터 시작하는 인덱스다. -1이면 탐험 시작 시 전체 층 중 하나를 선택하고, 1이면 두 번째 층에 만든다. 그 층 안의 위치는 알고리즘으로 결정한다.
- 계단 가까이에서 E로 위·아래 층을 이동한다. 해체나 전리품 배치 중에는 이동하지 않는다. 이동 중 대시는 끝내지만 체력·가방·대시 재사용 대기시간은 유지한다.
- 방문한 층의 몬스터 위치·타이머, 해체한 시체·해체 진행, 탐색 지도와 추가 포탈 위치는 보존한다. 돌아왔다고 몬스터나 전리품을 다시 추첨하지 않는다. 다른 층에 있는 동안 해당 층의 시뮬레이션은 진행하지 않는다.
- 포탈 탈출 시 현재 탐험의 전리품을 마을 창고로 회수한다. 어느 층에서든 사망하면 탐험 중 가방의 전리품과 미배치 전리품을 잃고 마을로 돌아간다. 이미 마을 창고에 보관한 물품은 유지한다.

## 저장과 기존 콘텐츠

층 이동 완료 후 자동 저장한다. 수동 저장·이어하기·정상 종료 저장도 현재 층과 방문한 층 상태를 포함한다. 방문하지 않은 층의 도면·스폰 프리팹 목록도 최초 입장 때 복사하므로 제작자가 이후 에셋을 편집해도 진행 중인 탐험의 구조는 유지된다. 기존 암호화 저장 경로와 보호 형식을 사용한다.

기존 세 단층 던전과 저장 파일도 유지한다. 제작 창의 **기존 맵을 도면으로 변환**으로 이전 템플릿을 편집 가능한 층 에셋으로 가져올 수 있다. 변환 전 저장은 기존 단층 도면으로 이어지고 새 탐험부터 제작한 층 구성을 사용한다. 저장 호환성을 위해 출시한 던전 ID·프리팹 ID는 변경하거나 등록에서 삭제하지 않는다.

샘플 **깊은 회수 유적**은 두 층으로 구성되며 추가 포탈은 두 번째 층에 있다. `Assets/Resources/Dungeons/deep-salvage.asset`과 옆의 `deep-salvage-floors` 폴더에서 확인할 수 있다. 기존 세 던전과 함께 카탈로그에 등록된다.

## 데이터와 제한

- DungeonDefinition: 던전 이름·고유 ID·층 에셋 목록·추가 포탈 층.
- DungeonFloorDefinition: 층 이름·고유 ID·도면·몬스터/시체 프리팹과 수량.
- DungeonFloorMap: 빈 공간·바닥·벽 타일과 입구·계단 위치. 씬 객체를 저장하지 않는다.
- DungeonExpeditionData: 현재 층, 추가 포탈 층, 각 층의 도면·스폰 목록과 방문 상태.

현재 도면 크기는 각 축 4~64칸, 던전은 최대 16층이다. 층별 몬스터·시체 합계는 256개와 배치 가능 칸 수 중 작은 값 이하, 던전 전체는 1024개 이하로 제한한다. 모두 연결된 바닥이어야 하며 입구·계단은 서로 다른 바닥 칸이어야 한다. 외곽 벽과 전체 바닥 버튼으로 기본 형태를 만들 수 있다. 크기를 줄일 때는 잘려 나간 입구·계단이나 통로를 다시 배치한 뒤 검증한다.

층 제외는 목록 참조만 제거하고 파일은 삭제하지 않는다. Undo로 생성 작업을 되돌려도 사용하지 않는 에셋이 남을 수 있다. 폴더를 수동 정리할 때 기존 저장에서 필요한 던전·프리팹 등록은 유지한다.

한 번에 현재 층의 메시·충돌·배우만 로드한다. 이동할 때 배우는 기존 풀에 반환하며 다음 층에서 재사용한다. 2.5D 표시와 2D 논리 좌표를 유지하고, 계단은 층별 씬 재구성으로 연결한다. 연속된 3D 높이 이동 방식은 아니다. 기존 MidtermProfiling 도구와 측정 결과는 그대로 유지한다.

## 검증

`Tools/Validate-GameFlow.ps1 -CaptureScreens`는 격리 프로젝트에서 도면 유효성, 기존 단층 호환, 계단 왕복, 체력·가방 유지, 방문 층 상태 보존, 깊은 층 저장·불러오기, 사망 시 회수품 손실을 검사한다. 일반 Windows 빌드와 독립 프로세스 재실행에서도 검증한다. 실제 층 화면은 `.utmp/UnityValidation/release-authored-floor.png`에 캡처한다.

2026-10-17 최종 검증: Unity 게임 흐름 532개, 일반 Windows 빌드 488개, 별도 프로세스 저장 복원 12개 통과. 32×20 도면을 실제 플레이·저장에서 유지하고 제작 에셋이 달라져도 진행 중 도면을 복원하는 것을 확인했다. 입구 포탈과 추가 포탈 회수, 깊은 층 사망도 검사했다. 검사 개수는 무작위 배치의 풀 재사용 수에 따라 달라질 수 있다.

입체 표시에서는 바닥 타일마다 숨겨진 GameObject/SpriteRenderer를 만들지 않는다. 현재 층의 합친 메시와 필요한 논리 충돌체만 구성한다. 성능 목표 달성 여부는 별도 프로파일링으로 측정해야 한다.
