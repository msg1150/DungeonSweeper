# 던전 제작과 여러 층 탐험

Unity 메뉴 **Dungeon Sweeper → Dungeon Builder**에서 제작 창을 연다. 별도 씬을 만들거나 게임 코드를 수정하지 않고 던전 도면과 층별 스폰 목록을 편집한다.

상단 왼쪽 **← 던전 목록**으로 기존 던전 선택 화면에 돌아간다. 목록에는 등록된 던전의 표시 이름·에셋 이름·저장 경로가 나오며, 원하는 항목을 누르면 편집할 수 있다. 돌아가도 편집 중인 에셋과 실행 취소 기록은 유지된다. 변경을 디스크에 기록하려면 **저장 + 게임에 등록**을 누른다. 자동 생성 화면에서 목록으로 돌아간 경우 후보도 유지되며, **자동 생성**을 다시 누르면 이어서 확인할 수 있다. **미리보기 닫기**는 후보를 해제한다.

## 던전 삭제

기존 던전을 선택한 뒤 상단 **새 던전** 오른쪽의 **던전 삭제**를 누른다. 플레이 중과 자동 생성 미리보기에서는 비활성화된다. 확인 창에서 던전 이름·에셋 경로·전용 층 수를 확인한 후 **삭제**를 누르면 카탈로그에서 제외하고 해당 파일들을 휴지통으로 보낸 뒤 목록으로 돌아간다.

다른 에셋이 참조하는 공유 층, 몬스터·시체 프리팹, 저장 파일과 프로파일링 폴더는 유지한다. 폴더 전체를 삭제하지 않으며, 이미 **층 제외**로 연결을 끊어 둔 층도 자동 삭제하지 않는다. 전용 층 일부를 옮기지 못하면 남은 경로를 제작 창에 표시한다. 삭제한 던전 안에서 저장한 진행은 카탈로그의 해당 던전이 없어 불러올 수 없으므로 유지해야 하는 진행이 있으면 삭제하지 않는다. 파일 삭제는 Ctrl+Z 대상이 아니며 복구가 필요하면 휴지통 또는 Git을 이용한다. 복구 후에는 **저장 + 게임에 등록**으로 다시 등록한다.

## 조건으로 자동 생성하고 채택하기

1. 상단의 **자동 생성**을 누른다. 던전 이름, 층 수, 기본 가로·세로 칸 수를 입력한다. 칸 수는 바닥뿐 아니라 벽·빈 공간을 포함한 도면 전체의 크기다.
2. 층마다 다른 크기를 원하면 **층마다 크기 지정**을 켜고 각 행에 가로·세로 칸 수를 입력한다. 지원 범위는 1~16층, 각 축 4~64칸이다.
3. **조건으로 생성**을 누른다. 생성기는 영역을 나눠 방을 만들고 통로로 연결하며, 벽과 입구·위/아래 계단도 배치한다. 모든 바닥과 계단이 입구에서 도달 가능한지 검증한다.
4. **미리볼 층** 목록에서 각 층을 확인한다. 확대·스크롤로 도면을 볼 수 있다. 이 단계의 후보는 메모리에만 있고 에셋 파일이나 게임 카탈로그에는 등록되지 않는다.
5. 마음에 들지 않으면 **다시 생성 (새 시드)**를 누른다. 같은 크기로 새 후보를 만든다. 생성 시드를 직접 입력하고 **조건으로 생성**을 누르면 같은 생성기 버전과 조건에서 같은 도면을 재현한다. 최소 크기처럼 가능한 형태가 적은 경우 다른 시드의 모양도 같을 수 있다.
6. 원하는 결과라면 **이 후보 채택 · 저장 + 게임 등록**을 누르고 새 에셋 경로를 선택한다. 화면에서 확인한 도면을 그대로 저장하며 채택 과정에서 다시 생성하지 않는다. 이후 기본 제작 화면에서 벽·계단을 직접 수정할 수 있다.

입력한 크기·층 수·시드를 변경한 경우 새 후보를 생성한 뒤 채택해야 한다. 미리보기 중에도 층별 몬스터·시체 수량과 추가 포탈 층을 조절할 수 있다. 기본 스폰은 등록된 종류당 최대 1개씩이며 작은 도면은 배치 용량에 맞춰 줄인다. **다시 생성**은 새 후보와 기본 스폰 목록을 만든다.

**미리보기 닫기** 또는 창 닫기는 후보를 해제한다. 저장 창에서 취소해도 에셋을 만들지 않는다. 채택은 새 던전으로 저장하므로 기존 에셋을 덮어쓰지 않는다. 채택 후에는 시드와 생성기 버전을 제작 창에서 확인할 수 있으며, 저장된 도면을 게임이 사용한다. 게임에 입장할 때 맵을 다시 생성하지 않는다.

## 제작 순서

1. **새 던전**을 누르고 Assets 아래에 데이터 에셋을 저장한다. 기본으로 연결된 방과 복도가 있는 첫 층을 만든다. 기존 던전을 편집하려면 상단 에셋 칸이나 시작 목록에서 선택한다.
2. 왼쪽 도구에서 **바닥 / 벽 / 빈 공간**을 선택하고 오른쪽 격자에서 드래그한다. 오른쪽 드래그는 빈 공간으로 지운다. Ctrl+Z로 한 번의 드래그를 취소할 수 있다. 확대 슬라이더와 스크롤로 넓은 도면을 편집한다.
3. **입구 기준**으로 첫 층의 귀환 포탈 위치를 정한다. **층 추가** 후 각 층의 위·아래 계단을 배치한다. 위층과 아래층의 계단 좌표는 서로 달라도 된다. 층 목록의 순서대로 연결된다.
4. 각 층의 **몬스터 / 시체** 목록에 프리팹과 수량을 넣는다. 위치를 도면에 직접 배치하지 않는다. 입장 시 알고리즘이 도달 가능한 바닥에서 위치를 선택하고 입구·계단 칸을 비워 둔다.
5. **검증 → 저장 + 게임에 등록**을 누른다. 도면·스폰 에셋을 저장하고 DungeonCatalog에 던전과 사용 프리팹을 자동 등록한다. 이후 마을 포탈에서 새 탐험을 시작하면 선택 대상에 포함된다.

**선택 던전만 바로 테스트하려면:** MainMenu에서 새 게임으로 마을에 들어간 후, 제작 창에서 원하는 던전을 선택하고 **선택 던전 입장**을 누른다. Play 중에는 도면 편집이 잠긴다. 기존 탐험의 도면은 저장 당시 스냅샷을 사용하므로 변경 확인은 새 탐험에서 한다.

## 던전별 시야·어둠

수동 편집과 자동 생성 화면의 **시야·어둠 (던전 전체)**에서 **선명 시야 반경 / 바깥 어둠 반경 / 바깥 어둠 강도**를 지정한다. 현재 기본값은 **3 / 5 / 0.9**이며 같은 던전의 모든 층에 적용한다. 던전 리소스 Inspector에서도 수정할 수 있고, 자동 생성의 후보를 채택할 때 함께 저장한다. 상세 동작과 확인 순서는 [던전 시야 설정](DUNGEON_VISION.md)을 참고한다.

## 은신처 배치와 사용

- 수동 편집: **은신처** 도구로 원하는 바닥 칸을 칠한다. 청록색 **H**로 표시되며, **은신처 지우기**는 바닥을 남기고 표식만 제거한다. 벽·빈 공간으로 바꾸면 해당 은신처도 제거한다. 입구·계단과 겹칠 수 없고 층마다 최대 64개다.
- 자동 생성: **층별 은신처 수**를 0~16으로 지정한다. 기본 2개이며 벽 근처와 서로 떨어진 위치를 우선한다. 작은 도면에서는 추가 포탈 공간을 남기고 가능한 수만 만든다. 은신처 수를 바꾼 경우 다시 생성한 뒤 채택한다.
- 저장 후 **새 탐험**에 들어가면 보관함 형태의 임시 모델로 표시된다. 입장 중인 탐험과 기존 저장은 당시 도면을 사용하므로 새 은신처가 소급 추가되지는 않는다. 발견한 은신처 칸은 미니맵에서 청록색으로 표시한다.
- 가까이서 **E**로 숨고 다시 **E**로 나온다. 아이템은 필요 없으며 은신 중 이동·대시·해체·층 이동은 할 수 없다. 게임과 몬스터의 순찰은 계속된다.
- 은신 중 플레이어의 물리 시뮬레이션을 잠시 제외해 지나가는 몬스터가 밀거나 통행에 막히지 않게 한다. 숨기 시작한 좌표를 저장하고, 나올 때 같은 좌표와 기존 물리 상태를 복원한다. 셀 중앙으로 강제로 이동시키지 않는다. 은신 중 저장 좌표도 이 위치를 사용한다.
- 숨는 순간, 같은 층 몬스터 중 하나라도 **Monster Prefab → Stats → Hiding Reveal Range** 이내에 있으면 발각되어 숨기가 실패한다. 기본값은 2 월드 단위다. 거리만 판정하며 벽이나 소음 시야 배율과 무관하다. 모두 반경 밖이면 즉시 추격·공격·마지막 목격 기록·기존 소음 조사를 끊는다.
- 성공한 뒤 몬스터가 가까워져도 자동 발각되지는 않는다. 나오면 평소 인식 규칙으로 다시 발견될 수 있다. 은신 진입·종료는 자동 저장하며, 은신 중 저장·로드하면 그 상태로 복원한다.
- 몬스터·시체·추가 포탈은 은신처 칸에 생성하지 않는다. 몬스터의 순찰 통행을 막는 벽으로 취급하지는 않는다.

### 확인 순서

1. 제작 창에서 은신처를 추가해 **검증 → 저장 + 게임에 등록**을 누르거나, 자동 생성에 은신처 수를 넣고 후보를 채택한다.
2. MainMenu에서 새 게임으로 마을에 간 뒤 제작 창의 **선택 던전 입장**으로 해당 던전을 테스트한다.
3. `DungeonTuning → Show Monster Perception Ranges`를 켜면 **보라색 원**으로 각 몬스터의 은신 발각 반경이 보인다.
4. 모든 보라색 원 밖에서 보관함 근처의 E 안내를 확인하고 숨는다. 플레이어가 사라지고 추격이 끊기며 이동·대시가 멈추는지 확인한다.
5. E로 나온 뒤 몬스터의 보라색 원 안에서 다시 숨기를 시도한다. 발각 안내와 함께 플레이어가 계속 노출되는지 확인한다.
6. 은신 중 수동 저장 후 불러와 은신 상태가 유지되고 E로 정상적으로 나올 수 있는지 확인한다.
7. 숨은 뒤 몬스터가 그 위치를 지나갈 때까지 기다렸다가 나온다. 처음 숨은 위치에서 나오는지, 다시 정상적으로 이동하고 벽과 충돌하는지 확인한다. 은신 중 저장·이어하기 후에도 같은 순서로 확인한다.

## 층과 탈출 규칙

- 첫 층에만 들어왔던 귀환 포탈이 있다. 깊은 층에서 입구로 탈출하려면 계단을 따라 첫 층까지 올라온다.
- 추가 탈출 포탈은 **던전 전체에 하나**다. `추가 포탈 층`은 0부터 시작하는 인덱스다. -1이면 탐험 시작 시 전체 층 중 하나를 선택하고, 1이면 두 번째 층에 만든다. 그 층 안의 위치는 알고리즘으로 결정한다.
- 계단 가까이에서 E로 위·아래 층을 이동한다. 해체나 전리품 배치 중에는 이동하지 않는다. 이동 중 대시는 끝내지만 체력·가방·대시 재사용 대기시간은 유지한다.
- 방문한 층의 몬스터 위치·타이머, 해체한 시체·해체 진행, 탐색 지도와 추가 포탈 위치는 보존한다. 돌아왔다고 몬스터나 전리품을 다시 추첨하지 않는다. 다른 층에 있는 동안 해당 층의 시뮬레이션은 진행하지 않는다.
- 포탈 탈출 시 현재 탐험의 전리품을 마을 창고로 회수한다. 어느 층에서든 사망하면 탐험 중 가방의 전리품과 미배치 전리품을 잃고 마을로 돌아간다. 이미 마을 창고에 보관한 물품은 유지한다.

## 저장과 기존 콘텐츠

층 이동 완료 후 자동 저장한다. 수동 저장·이어하기·정상 종료 저장도 현재 층과 방문한 층 상태를 포함한다. 방문하지 않은 층의 도면·스폰 프리팹 목록도 최초 입장 때 복사하므로 제작자가 이후 에셋을 편집해도 진행 중인 탐험의 구조는 유지된다. 기존 암호화 저장 경로와 보호 형식을 사용한다.

기존 세 단층 던전과 저장 파일도 유지한다. 제작 창의 **기존 맵을 도면으로 변환**으로 이전 템플릿을 편집 가능한 층 에셋으로 가져올 수 있다. 변환 전 저장은 기존 단층 도면으로 이어지고 새 탐험부터 제작한 층 구성을 사용한다. 저장 호환성을 위해 출시한 던전 ID·프리팹 ID는 변경하거나 등록에서 삭제하지 않는다.

샘플 **깊은 회수 유적**은 두 층으로 구성되며 추가 포탈은 두 번째 층에 있다. `Assets/Resources/Dungeons/deep-salvage.asset`과 옆의 `deep-salvage-floors` 폴더에서 확인할 수 있다. 기존 세 던전과 함께 카탈로그에 등록된다.

## 데이터와 제한

- DungeonDefinition: 던전 이름·고유 ID·층 에셋 목록·추가 포탈 층.
- DungeonFloorDefinition: 층 이름·고유 ID·도면·몬스터/시체 프리팹과 수량.
- DungeonFloorMap: 빈 공간·바닥·벽 타일과 입구·계단 위치. 씬 객체를 저장하지 않는다.
- DungeonExpeditionData: 현재 층, 추가 포탈 층, 각 층의 도면·스폰 목록과 방문 상태.

현재 도면 크기는 각 축 4~64칸, 던전은 최대 16층이다. 층별 몬스터·시체 합계는 256개와 배치 가능 칸 수 중 작은 값 이하, 던전 전체는 1024개 이하로 제한한다. 모두 연결된 바닥이어야 하며 입구·계단은 서로 다른 바닥 칸이어야 한다. 외곽 벽과 전체 바닥 버튼으로 기본 형태를 만들 수 있다. 크기를 줄일 때는 잘려 나간 입구·계단이나 통로를 다시 배치한 뒤 검증한다.

층 제외는 목록 참조만 제거하고 파일은 삭제하지 않는다. Undo로 생성 작업을 되돌려도 사용하지 않는 에셋이 남을 수 있다. 폴더를 수동 정리할 때 기존 저장에서 필요한 던전·프리팹 등록은 유지한다.

한 번에 현재 층의 메시·충돌·배우만 로드한다. 이동할 때 배우는 기존 풀에 반환하며 다음 층에서 재사용한다. 2.5D 표시와 2D 논리 좌표를 유지하고, 계단은 층별 씬 재구성으로 연결한다. 연속된 3D 높이 이동 방식은 아니다. 기존 MidtermProfiling 도구와 측정 결과는 그대로 유지한다.

## 검증

`Tools/Validate-GameFlow.ps1 -CaptureScreens`는 격리 프로젝트에서 도면 유효성, 기존 단층 호환, 계단 왕복, 체력·가방 유지, 방문 층 상태 보존, 깊은 층 저장·불러오기, 사망 시 회수품 손실을 검사한다. 일반 Windows 빌드와 독립 프로세스 재실행에서도 검증한다. 실제 층 화면은 `.utmp/UnityValidation/release-authored-floor.png`에 캡처한다.

2026-10-17 최종 검증: Unity 게임 흐름 532개, 일반 Windows 빌드 488개, 별도 프로세스 저장 복원 12개 통과. 32×20 도면을 실제 플레이·저장에서 유지하고 제작 에셋이 달라져도 진행 중 도면을 복원하는 것을 확인했다. 입구 포탈과 추가 포탈 회수, 깊은 층 사망도 검사했다. 검사 개수는 무작위 배치의 풀 재사용 수에 따라 달라질 수 있다.

2026-10-18 자동 생성 추가 검증: Unity 게임 흐름 536개, Windows 빌드 500개, 별도 프로세스 저장 복원 12개 통과. 4×4, 4×64, 64×4, 20×12, 32×20, 64×64 크기별 20개 시드에서 층 연결·정확한 크기·닫힌 외곽을 확인했다. 층별 다른 크기, 동일 시드 재현, 새 시드 재생성, 미리보기 무등록, 폐기·취소 시 무기록, 채택 시 검토한 도면 그대로 저장하는 것도 검사했다. 수동 도면으로 변환한 기존 에셋을 보존하면서 코드 기반 단층 호환·풀 용량 검사도 수행한다.

입체 표시에서는 바닥 타일마다 숨겨진 GameObject/SpriteRenderer를 만들지 않는다. 현재 층의 합친 메시와 필요한 논리 충돌체만 구성한다. 성능 목표 달성 여부는 별도 프로파일링으로 측정해야 한다.
