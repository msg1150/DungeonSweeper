# 저장 보호와 복원

현재 보호 대상은 Windows Editor와 Windows 플레이어입니다. 서버를 두지 않는 오프라인 게임에서 일반적인 저장 파일 편집과 슬롯 바꿔치기를 막는 것을 목표로 합니다.

## 파일과 검증

- 위치: `Application.persistentDataPath/Saves`.
- 자동 저장: `autosave.sav` 1개.
- 수동 저장: `slot-01.sav`부터 시작하며 `GameFlowConfig.manualSaveSlotCount`로 개수를 조정합니다.
- 파일 안의 직렬화된 진행도는 Windows DPAPI로 암호화합니다. OS가 암호문의 무결성을 확인한 뒤 복호화하며, 게임은 복호화된 진행도의 버전·범위·구조도 검사합니다.
- 암호화 키를 게임 소스, PlayerPrefs 또는 저장 폴더에 평문으로 기록하지 않습니다.
- 슬롯마다 보호 목적을 구분합니다. 같은 파일의 이름만 바꾸어 다른 슬롯이나 자동 저장으로 읽는 것을 거부합니다.
- 파일 크기, 헤더, 위치·수치의 유한성, 가방 셀 충돌, 중복 ID와 이벤트 등도 검증합니다.

저장할 때 암호화된 임시 파일을 먼저 기록하고 교체합니다. 이전 정상 저장본은 암호화된 `.bak`으로 보관합니다. 주 저장본이 변조되거나 손상되면 검증을 통과한 백업을 읽으며, 둘 다 사용할 수 없으면 불러오기를 거부합니다. 손상된 주 저장본을 다음 백업으로 덮어 정상 백업을 잃지 않도록 처리합니다.

자동 저장 실패 시 요청을 유지하고 5초 뒤 최신 상태로 재시도합니다. 정상 복귀·종료 저장에 실패하면 복귀·종료를 취소하고 현재 게임을 유지합니다. 강제 프로세스 종료와 전원 차단에서는 마지막 성공한 저장 이후의 변경을 잃을 수 있습니다.

## 복원되는 상태

마을의 골드·의뢰·보급 도구·위치, 플레이 시간과 완료 이벤트를 기록합니다. 던전 저장에는 레이아웃, 플레이어 위치·체력·대시 방향/남은 시간/쿨다운·피격 무적 시간, 탐색 지도, 가방, 시체와 해체 진행, 미배치 전리품, 몬스터 상태가 포함됩니다.

전리품 정리 화면에서 저장했다면 불러온 뒤 정리 화면과 게임 정지도 복원합니다. 새로 추가된 탐색·이동 필드가 없는 기존 암호화 저장은 기존 필드를 읽고 새 필드를 기본값으로 처리합니다. 미래의 저장 구조 변경은 `GameSaveData`의 버전·호환 처리와 함께 관리해야 합니다.

마을 창고의 종류별 가격·수량·판매 잠금과 가방 확장 단계도 저장합니다. 귀환 시 던전 가방의 소유권을 창고로 이전하며, 거래와 업그레이드는 아이템·골드를 함께 변경한 뒤 저장합니다. 기존 저장에 새 필드가 없으면 빈 창고와 기본 5×4 가방으로 처리하고 기존 골드를 유지합니다. 전리품 종류 ID와 배포된 가방 확장 단계 순서는 업데이트 후에도 유지해야 합니다.

## 개발 저장 이전

과거 JSON 파일과 단일 PlayerPrefs 진행도 가져오기는 **Unity Editor에서만** 실행합니다. JSON의 주 저장본과 정상 백업을 보호 파일로 변환하고 검증한 뒤 평문 원본을 제거합니다. 변환 실패 시 평문 원본을 유지합니다.

출시 빌드는 이 이전 코드를 포함하지 않습니다. 사용자가 평문 JSON이나 PlayerPrefs 진행도를 만들어 암호화 검사를 우회하는 경로는 제공하지 않습니다. 게임 옵션만 별도 PlayerPrefs 설정으로 유지합니다.

## 현재 한계와 배포 정책

DPAPI는 Windows 사용자에 묶인 보호입니다. 일반적으로 같은 PC와 Windows 계정에서만 복호화할 수 있습니다. 저장 파일만 다른 PC/계정으로 복사하거나 Windows를 재설치하면 불러오지 못할 수 있습니다. PC 이전·클라우드 동기화를 제공하려면 별도의 인증 또는 내보내기 정책을 설계하고 검증해야 합니다.

같은 슬롯의 과거 정상 저장본을 다시 사용하는 것은 허용합니다. 서버가 없으므로 과거 저장으로 되돌리는 동작을 확실히 차단하지 않습니다. 같은 Windows 계정에서 DPAPI를 직접 사용하는 도구, 게임 메모리·실행 파일 변조까지 방지하지 않습니다.

다른 OS는 보호 제공자를 구현하기 전까지 저장과 빌드를 거부합니다. 평문 저장으로 우회하지 않습니다. 출시 시 회사명·제품명은 저장 경로에도 영향을 주므로 최종 배포 전에 확정하고, 배포 후 변경한다면 이전 경로에서 읽는 정책이 필요합니다.
