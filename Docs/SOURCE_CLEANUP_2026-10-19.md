# 2026-10-19 미사용 코드·설정 정리

앞선 점검에서 같은 `DungeonDefinition`을 대상으로 하는 Inspector 두 개가 남아 있었다. 그중 구 Inspector가 층별 던전에서 사용하지 않는 루트 스폰 배열과 옛 레이아웃을 표시했다. 이번에는 프로젝트의 런타임·에디터 코드 호출, 씬·프리팹·데이터의 GUID 참조, 메뉴와 Inspector 등록을 함께 확인했다. 프로파일링 코드는 정리 대상에서 제외했다.

## 제거한 코드와 씬 구성

- 중복 `DungeonDefinitionEditor`를 삭제하고 층별 정보를 표시하는 Inspector 하나로 통합했다. 던전 화면에서 각 층의 몬스터·시체 합계를 보고 **N층 생성 수 설정 열기**로 실제 설정을 편집한다.
- 현재 런 컨트롤러가 시작할 때 항상 비활성화하던 `PlayerInteractor`, `IInteractable`, `CorpseInteractable`, `DismantleController`와 관련 `.meta`를 삭제했다. 현재 상호작용·해체는 `DungeonRunController`와 `DismantleSession`이 계속 담당한다.
- `Dungeon_Test`의 옛 시체·해체 패널·Canvas·EventSystem·테스트 벽을 현재의 최소 던전 씬 구성으로 교체했다. 씬 파일과 GUID는 유지한다. 이제 `Dungeon`과 `Dungeon_Test` 모두 카메라·플레이어·런 컨트롤러를 직접 포함한다.
- `Dungeon`의 런타임에서 사용하지 않는 정적 방·벽·구분선을 제거했다. 이에 따라 매 입장 시 모든 충돌체·스프라이트를 검색해서 비활성화하던 정리 메서드와 옛 상호작용 검색도 삭제했다. 실제 벽·바닥은 기존 층 도면으로 생성한다.
- 런 컨트롤러가 없을 때 대신 만드는 `DungeonTestBootstrap`은 두 씬에 더 이상 필요하지 않아 소스와 `.meta`를 삭제했다.
- 호출과 직렬화 이벤트 참조가 없는 `RandomGateSpawn`, `GameAudio.PlayEffect`, `ThreeDActorView.CurrentAnimation`을 제거했다.
- 씬에 남아 있었지만 현재 `PlayerMovement`에는 존재하지 않는 옛 이동·대시 직렬화 값을 제거했다. 실제 이동 수치는 기존 `DungeonTuning`을 따른다.

## 편집 화면의 단일 설정 경로

고유 ID·층 연결을 구성하지 않는 옛 `Create → Dungeon / Dungeon Floor / Monster Database` 메뉴도 제거했다. 새 던전과 층은 제작 툴에서 만들며, 기본 내부 데이터는 기존 초기화 도구가 관리한다.

| 항목 | 실제 편집 위치 |
| --- | --- |
| 던전 이름·난이도·선택창 이미지·설명 | 던전 Inspector 또는 제작 툴 |
| 몬스터·시체 생성 수 | 각 층 에셋 또는 제작 툴의 편집할 층 |
| 몬스터 이동·순찰·인식·공격 | `Assets/Prefabs/Monsters`의 Stats |
| 시체 해체·전리품 | `Assets/Prefabs/Corpses` |
| 플레이어 이동·체력·시야·풀 한도 | `DungeonTuning` |

현재 던전과 몬스터에 적용되지 않는 옛 루트 스폰·레이아웃·전역 몬스터 조절 항목은 일반 Inspector에 노출하지 않는다. `MonsterDatabase`의 옛 능력치·전리품 편집 UI도 제거하고 실제 프리팹 폴더로 이동하도록 바꿨다. 이 데이터는 기본 콘텐츠 생성과 구 저장 복원에 실제로 사용하므로 소스와 저장 필드를 삭제하지 않는다.

2.5D를 선택했을 때는 3D 모델 연결과 원근 카메라 항목이 나타나지 않는다. 모델 표시를 선택하면 해당 항목을 다시 편집할 수 있다. 몬스터·시체 프리팹도 현재 표시 방식의 모델 설정만 노출하고, 시트 사용을 껐으면 적용되지 않는 시트 설정을 숨긴다. 기본 생성용 공격 유형 메타데이터는 현재 프리팹의 공격 그림을 바꾸는 설정이 아니므로 노출하지 않는다.

새 층을 추가할 때 무시되어야 할 구 루트 배열을 복사하던 경로도 수정했다. 구 단층 도면 변환에만 그 배열을 사용하고, 변환 완료 후 루트 배열은 비운다. 명시적으로 비어 있던 시체 목록도 변환 과정에서 보존한다. 이후 추가하는 층은 등록 프리팹의 기본 수량으로 독립 구성한다.

## 추가로 확인한 에디터 오류

컴포넌트를 편집기에서 추가하는 검사 중 `Failed to call static function Reset because an object was provided`가 기록되었다. Unity의 인스턴스 `Reset` 콜백과 같은 이름을 쓴 정적 초기화 메서드가 원인이었다. 관련 컴포넌트·설정의 메서드를 `ResetRuntimeState`로 변경하고 기존 런타임 초기화 특성은 유지했다.

## 검증

`Tools/Validate-GameFlow.ps1 -EditorOnly`는 별도 `.utmp/UnityValidation`에서 컴파일하고 다음을 확인한다. 이 모드는 플레이 모드·Windows 게임 실행·빌드를 수행하지 않는다.

- 프로젝트 Inspector 대상 중복과 올바른 던전 Inspector 선택
- 옛 단층·전역 몬스터 필드가 일반 표시 목록에서 제외되는지 확인
- 삭제한 타입이 컴파일 결과에 남지 않는지 확인
- MainMenu·Town·Dungeon·Dungeon_Test의 끊어진 스크립트 참조 검사
- 던전 두 씬의 플레이어·런 컨트롤러와 정적 충돌체 정리 확인
- 구 도면 변환의 수량·빈 목록 보존, 비활성 배열 정리, 새 층의 독립 생성
- 생성 후보 채택 시 난이도·이미지·설명 보존과 던전 선택 데이터 검사
- 정적 `Reset` 콜백 충돌 방지

최종 Unity 6000.6.0f1 실행은 **에디터 검사 56개 통과**, 종료 코드 0이었다. 최종 로그에 C# 컴파일 오류·경고, 검사 예외, 정적 Reset 충돌 또는 GUI 오류가 남지 않았다. 삭제한 상호작용·해체 스크립트 GUID의 씬·프리팹·데이터 참조도 남지 않았다. 단일 참조로 남은 메서드는 런타임 초기화·에디터 초기화·메뉴 특성으로 Unity가 직접 호출하는 진입점임을 확인했다.

플레이 조작과 화면 확인은 사용자가 수행한다. 확인할 항목은 던전 Inspector에 층별 수량과 난이도가 표시되는지, 각 층의 Count 변경이 새 입장에 반영되는지, 마을 입장 선택·던전 이동·시체 해체·층 이동·이어하기가 이어지는지다. `Dungeon_Test` 직접 실행도 현재 런 컨트롤러로 시작한다.

사용자가 제작 중인 던전 도면·프리팹 수치·카탈로그 편집과 실제 저장 파일은 이번 정리에서 변경하지 않았다. 구 저장의 해석과 등록 프리팹 복원 경로, 요청된 미래 이미지·영상·사운드 연결 지점, 선택 가능한 3D 표시 경로는 용도가 남아 있어 유지한다. `Assets/MidtermProfiling/`, `.meta`·`.asmdef`, 활성화 조건과 기존 측정 결과도 유지했다.
