# 출시 준비 점검 기록

2026-10-07 기준으로 현재 플레이 흐름과 설정을 검토했습니다. 아래 기록은 구현된 프로토타입의 안정성 보강과 검증 범위를 설명하며, 완성 게임의 출시 승인을 의미하지 않습니다.

## 수정한 항목

| 영역 | 발견한 문제와 수정 |
| --- | --- |

| 던전 배치·순찰 | 비어 있는 런타임 몬스터 목록에는 기본 3종을 사용하되 원본 에셋은 변경하지 않습니다. 첫 시체를 초반 탐색 구역에 배치하고 개체를 분산합니다. 순찰 중 주기적인 목적지 재선정을 없애고 먼 목적지까지 통로를 따라 이동한 후 짧게 대기합니다. 이전 구역으로 바로 되돌아가는 선택을 줄이고 소음 조사 후 넓은 순찰을 재개합니다. |

| 풀·최적화 | 프리팹별 몬스터·시체 풀을 추가하고 씬 이동 전에 반환합니다. 이전 공격·조사·애니메이션 상태와 플레이어 참조를 지우고, 시체 런 데이터는 별도로 생성합니다. 경로 탐색 작업 배열·시야 결과 리스트·창고 표시·회전 미리보기를 재사용하며 가공 텍스처 사본의 CPU 픽셀 버퍼를 해제합니다. 상세 규칙과 측정 범위는 [성능 검토](PERFORMANCE_REVIEW.md)에 정리했습니다. |
| 추가 코드 검토 | 로딩 중 새 게임·불러오기의 중복 전환, 특정 던전 입장에서의 프리팹 등록 누락, 마을 버튼의 입력 차단 덮어쓰기를 방어했습니다. 큰 해체 성공 영역과 지연 프레임의 포인터 반사를 보강하고, 자동 생성 도구가 타입을 읽지 못하는 기존 에셋을 덮어쓰지 않도록 수정했습니다. |
| 이어하기 첫 입장 | Unity 직렬화로 마을 저장에도 빈 던전 객체가 들어가는데, 객체 존재만으로 복원 대기 상태를 설정하여 첫 입장에 레이아웃 0·체력 1·개체 0개를 적용하던 문제를 수정했습니다. 저장 지역이 던전인 경우에만 복원하고, 마을에서 새로 입장하거나 귀환할 때 복원 대기 상태를 비웁니다. 기존 마을 저장은 삭제 없이 호환합니다. |
| 옵션 | 기본 프레임 설정도 실행 시 적용하고 초기 기본값을 보존합니다. 옵션 초안을 적용한 뒤 수정해도 적용 상태가 바뀌지 않도록 복사하고, 비정상 음량·과도한 해상도를 제한합니다. |
| HUD·전리품 | 논리 화면 크기로 배치해 창 크기에 맞춰 축소합니다. 많은 전리품을 스크롤하고, 목록 변경·메뉴 전환 후 남는 드래그 상태와 오래된 인덱스를 정리합니다. |

| 빌드 | 필수 씬 순서·리소스·컴포넌트·설정값과 몬스터 데이터를 검사하는 전처리 검증을 추가했습니다. Windows 비개발 빌드 메뉴를 제공합니다. |
| 마을 경제 | 귀환 자동 판매를 없애고 회수품을 무제한 수량 창고로 이전합니다. 거래소에서 가격별로 1개씩 판매하며, 판매 잠금·검색·정렬을 제공합니다. 골드와 재료를 함께 소비하는 가방 확장과 길드 직접 제출을 추가했습니다. |

## 실행 검증

검증 도구는 원본 프로젝트를 `.utmp/UnityValidation`에 복사하여 실행합니다. 테스트용 저장 경로와 회사명·제품명을 사용하며, 실제 플레이어의 저장과 옵션을 변경하지 않습니다.

2026-10-06에 `./Tools/Validate-GameFlow.ps1 -CheckPlayerProtection -CaptureScreens`를 실행한 결과:

| 검사 | 결과 |
| --- | --- |
| Unity 6000.6.0f1 런타임 | 390개 통과 |
| Windows 64비트 비개발 Mono 플레이어 | 빌드 성공, 132개 통과 |
| 별도 프로세스 재실행 | 3개 통과 |
| 화면 | 1280 × 720 및 640 × 360, 창고·거래소·확장 가방 포함 촬영 11장 확인 |

2026-10-07 포커스 처리 변경 후 `./Tools/Validate-GameFlow.ps1 -CheckPlayerProtection`를 실행해 Unity 런타임 420개, Windows 비개발 Mono 플레이어 141개, 별도 프로세스 재실행 3개 검사를 통과했습니다. 화면 없는 테스트 환경에서는 포커스 콜백을 명시적으로 호출하여 메뉴 없는 정지·자동 재개, 반복 전환, 기존 정지 화면 유지, 복귀 프레임 입력 차단과 백그라운드 씬 로딩을 검사했습니다. 이 실행에서는 화면을 재촬영하지 않았습니다.

같은 날 배치·순찰 변경 후 Unity 런타임 444개 검사를 통과했습니다. Windows 첫 실행은 손상 저장본을 교체하는 `File.Replace` 검사에서 운영체제 오류("바꿀 파일을 제거할 수 없습니다")로 중단되었습니다. 동일 빌드를 다시 실행해 Windows 검사 200개와 별도 프로세스 재실행 3개를 통과했으며, `player-protection-rerun-*.log`에 결과를 보존했습니다. 간헐적 파일 오류의 원인은 확정하지 못했으며, 기존 저장 실패 처리와 자동 저장 재시도는 유지합니다.

배치 검사는 세 레이아웃 각각 100개 시드에서 입구 연결·시체 분산·몬스터 초기 거리·먼 순찰 목표를 확인하고, Windows에서는 메인 메뉴부터 새 게임을 6회 시작해 세 맵의 실제 시체·몬스터 각 3개와 활성 렌더러를 확인했습니다. 빈 몬스터 목록을 주입한 첫 입장에서도 기본 3종을 생성했습니다. 통로 이동·벽 충돌·순찰 목적지 유지·소음 조사 후 이동·이전 저장의 순찰 상태 복원도 검사했습니다. 기존 화면 11장과 전체 맵 확인용 3장을 촬영했습니다. 전체 맵 촬영은 검사 복사본에서만 시야 오버레이를 숨겼습니다. 사용자가 보고한 첫 입장의 빈 던전은 정상 몬스터 설정으로 재현되지 않아 실제 원인은 확정하지 못했습니다.

같은 날 던전별 프리팹 구현 후 `./Tools/Validate-GameFlow.ps1 -CheckPlayerProtection -CaptureScreens`를 실행해 Unity 런타임 444개, Windows 비개발 Mono 플레이어 250개, 별도 프로세스 재실행 3개 검사를 통과했습니다. 기본 세 맵의 전체 배치 화면을 포함해 14장을 확인했습니다. 위에서 기록한 저장 파일 교체 오류는 이 실행에서 발생하지 않았습니다.

추가 검사는 몬스터 3마리·시체 4개, 시체만 2개, 몬스터만 2마리, 명시적으로 빈 던전을 실제 씬에서 생성합니다. 프리팹별 종류·수량·컴포넌트·능력치 복사와 위치 구분을 확인하며, 각 레이아웃의 최대 용량(163/154/157개)에서도 입구·게이트와 최초 배치 셀이 겹치지 않는지 검사합니다. 음수·누락 프리팹·용량 초과를 거부하고, 스폰 행을 모두 제거하고 프리팹 능력치를 변경한 뒤 저장된 개체 수·능력치·시체 난이도·해체 진행·전리품을 그대로 복원했습니다. ID 없는 이전 형식도 실제 씬에서 불러왔습니다. 기존 데이터베이스를 비우는 검사는 이제 새 입장이 독립적인 프리팹 설정을 사용하는지 확인합니다.

이어하기 후 첫 입장 문제는 마을 저장의 지역 값은 Town이지만 체력 0·개체 0개인 던전 객체가 함께 직렬화된 상태에서 재현했습니다. 수정 전 회귀 검사가 실패한 결과는 `continue-entry-before-fix.txt`와 `.log`에 남겼습니다. 수정 후 `./Tools/Validate-GameFlow.ps1 -CheckPlayerProtection`에서 Unity 런타임 457개, Windows 비개발 Mono 플레이어 293개, 별도 프로세스 재실행 10개 검사를 통과했습니다. 일반 수동·자동 마을 저장과 남은 던전 객체가 있는 이전 저장을 이어한 뒤 첫 입장·귀환·재입장을 검사했으며, 골드·창고·의뢰·가방 확장·완료 이벤트를 유지했습니다. 실제 프로세스를 재실행한 후에도 마을 저장을 이어서 선택한 던전에 입장해 최대 체력·입구 위치·프리팹 수량을 확인했습니다. 기존 던전 저장의 위치·체력·해체 상태 복원 검사도 함께 통과했습니다. 이 실행에서는 화면을 재촬영하지 않았습니다.

프리팹 폴더 이동 후 같은 명령으로 Unity 런타임 452개, Windows 비개발 Mono 플레이어 296개, 별도 프로세스 재실행 10개 검사를 통과했습니다. 이동한 24개 파일의 내용과 메타 파일은 이동 전과 동일합니다. 던전 목록 없이도 등록된 프리팹 ID를 조회하고, 등록을 누락한 스폰 행을 거부하며, 스폰 행을 제거한 뒤에도 저장된 개체를 복원했습니다. 이전 검사 복사본에 남은 Resources 프리팹은 검증 도구에서 정리해 중복 GUID를 방지합니다. 이 실행에서는 화면을 재촬영하지 않았습니다.

원본 프로젝트의 현재 Editor.log에서 확인한 `Deleting invalid font reference` 경고는 Unity TextCore의 `TextSettings.InitializeFontReferenceLookup`과 에디터 폰트 캐시 초기화에서 발생했습니다. [Unity 공개 소스](https://github.com/Unity-Technologies/UnityCsReference/blob/master/Modules/TextCoreTextEngine/Managed/TextAssets/TextSettings.cs)는 폰트 또는 FontAsset 참조가 null이면 이 경고를 기록하고 항목을 제거합니다. 현재 로그에는 C# 컴파일 오류나 게임 코드 예외가 보이지 않습니다. 이 경고의 재발 방지를 위해 에디터 캐시나 폰트 에셋을 변경하지 않았으며, 검증 빌드와 플레이는 정상 완료했습니다.

전체 플레이 코드 검토와 풀 도입 후 최종 `-CheckPlayerProtection` 실행에서 Unity 런타임 497개, Windows 비개발 Mono 플레이어 359개, 별도 프로세스 재실행 10개 검사를 통과했습니다. 직전 `-CaptureScreens` 실행은 런타임 485개·플레이어 361개·재실행 10개를 통과하고 화면 14장을 확인했습니다. 폴더·에셋·등록 ID와 기존 저장 형식은 유지했습니다. 추가 검사는 풀의 중복 반환·상태 초기화·시트 애니메이션 전환·새 시체 세션·보관 한도·0개 보관 설정, UI 캐시의 재사용과 갱신, 큰 해체 영역·지연 프레임, 텍스처 사본의 CPU 버퍼 해제를 검사합니다. Windows에서는 세 레이아웃 반복 입장과 저장 복원 이후 최대 163개 스폰 및 귀환 시 64개 보관, 메인 화면에서 캐시 해제도 통과했습니다. 경로 탐색은 세 레이아웃에서 예열 후 128회씩 호출하여 관리 메모리 할당 0바이트를 확인했습니다. 마지막 실행의 소스가 현재 런타임·에디터·리소스·프리팹 파일과 일치하는 것을 확인했습니다. 실제 FPS 향상이나 장시간 메모리 사용량은 별도 프로파일링 대상입니다.

- **Unity 런타임**: 메뉴·새 게임·옵션·슬롯 목록·저장 복원·해체·던전 배치·적 상태·의뢰/보상·자동 저장·백업 복구·정상 종료와 잘못된 데이터를 검사합니다.
- **Windows 비개발 Mono 빌드**: 메뉴에서 마을·던전 입장, 슬롯 복원, 전리품 화면, 탈출 정산·중복 정산 방지·사망 손실, 포커스 일시정지, 자동 저장 실패/회복을 검사합니다.
- **저장 보호**: DPAPI 왕복, 헤더·암호문·슬롯 변조 거부, 평문 저장 거부, 백업·임시 파일 보호, Editor 이전과 출시 빌드의 이전 차단을 검사합니다.
- **별도 프로세스 재실행**: 수동 슬롯과 정상 종료 자동 저장이 새 프로세스에서 동일하게 읽히는지 검사합니다.
- **창고·성장**: 자동 판매 방지, 중복 이전 방지, 종류 ID 구분, 개별 가격 보존, 판매 잠금, 재료·골드 부족 시 무차감, 저가 재료 우선 소비, 두 단계 가방 확장, 최대 단계 중복 결제 거부, 직접 의뢰 제출과 사망 시 창고 유지, 이전 저장 호환을 검사합니다.
- **화면 촬영**: 그래픽 모드에서 메인 메뉴·마을·던전·전리품 목록·스크롤 상태와 최소 640 × 360 창을 촬영합니다. 촬영 자체는 실제 마우스 드래그의 기능 검사를 대신하지 않습니다.

결과와 로그는 `validation-result.txt`, `unity-validation.log`, `player-build.log`, `player-protection-*.log`에서 확인합니다. 데이터에 따라 생성되는 던전 개체 수가 달라 개별 검사 횟수도 달라질 수 있습니다.

그래픽 플레이어 종료 시 `ComputeBuffer` 해제와 D3D12 리소스 정리 경고가 기록되었습니다. 프로젝트의 C# 코드에는 해당 버퍼 생성 코드가 없으며, 이 검사만으로 원인을 확정하지 못했습니다. 장시간 성능 검증에서 실제 리소스 증가 여부를 측정하고 최종 그래픽 API·렌더 파이프라인에서도 재현 여부를 확인해야 합니다. 빌드와 플레이 검사는 정상 완료했습니다.

## 출시 전에 완료할 항목

1. **미디어와 사용 권한** — 최종 배경·영상·음악·효과음·한글 글꼴을 연결하고 사용/배포 권한과 크레딧을 확인합니다. 현재 미디어 설정은 연결 구조를 제공하는 상태입니다.
2. **실제 플레이 QA** — 마우스 드래그·회전·스크롤, 다양한 화면 비율·배율, Alt-Tab, 미디어 재생·음량을 직접 확인합니다. 여러 PC에서 장시간 플레이, 반복 씬 이동, 메모리·프레임 성능을 측정합니다.
3. **콘텐츠와 밸런스** — 던전 수, 몬스터·보상·의뢰, 해체 난이도와 경제를 확정합니다. 현재 메뉴·HUD의 데모 표기도 최종 문구로 교체합니다.
4. **배포 설정** — 회사명·제품명·버전·아이콘·배포 채널을 확정합니다. 최종 백엔드가 IL2CPP라면 해당 빌드에서도 저장 보호와 전체 흐름을 재검증합니다. 현재 실제 플레이어 검증은 Windows 64비트 Mono 기준입니다.
5. **저장 정책** — Windows 계정/PC에 묶이는 DPAPI의 제약을 안내하고 PC 이전·클라우드 저장 제공 여부를 확정합니다. 향후 업데이트로 데이터 구조가 바뀌면 기존 저장 호환 검사를 추가합니다.

지원 범위를 확장할 때는 새 OS의 저장 보호 제공자와 그 플랫폼의 실제 빌드 검증부터 추가합니다.
