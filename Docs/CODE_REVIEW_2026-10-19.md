# 2026-10-19 중간 점검 및 최적화

이전 점검 이후 추가한 추격·은신·상태 표시·던전 제작 경로를 중심으로 런타임 표시, 풀 재사용, 저장 복원, UI 및 생성 코드를 다시 확인했다. 확인된 반복 계산과 상태 초기화를 수정했다.

## AI

- 추격 지름길의 몸체 BoxCast 검사를 이동 루프 밖으로 옮겼다. 목표 직행 검사 1회와 경로 생략 검사 최대 8회로, 한 이동 호출의 물리 검사 수를 제한한다. 프레임이 길어 여러 칸을 지나도 검사 예산이 반복해서 늘어나지 않는다. 시야 Raycast는 별도로 유지한다.
- 인식·소음·공격·도착 판정에서 거리 자체가 필요 없는 비교는 제곱 거리로 처리한다. 시야와 이동 쿼리의 배우 제외 규칙을 공통 메서드로 묶었다. 트리거 포함 여부는 각 쿼리의 기존 설정을 유지한다.
- 저장 복원 시 이전 경로 목록과 인덱스를 함께 비워 현재 상태로 경로를 다시 찾는다.
- 인식 거리·추격 속도·은신 발각 거리·공격 수치·순찰 대기 시간은 변경하지 않았다.

## 2.5D 표시와 자원

- 카메라 회전으로 결정되는 수직 스프라이트 방향과 세로 보정값을 월드에서 공유한다. 카메라 위치만 움직일 때는 다시 계산하지 않으며, 회전이 바뀌면 같은 프레임 안에서도 갱신한다.
- 스프라이트·색·뒤집기·정렬 순서·활성 상태는 값이 달라졌을 때만 해당 렌더러/오브젝트에 전달한다. 그림자 크기와 정렬 순서는 생성할 때, 색과 재질은 월드에 연결할 때 설정한다. 이동하는 위치는 계속 갱신한다.
- 느낌표/물음표와 선택 가능한 3D 표시도 동일한 활성 상태를 매 프레임 다시 설정하지 않는다. 기존 표시 객체와 공용 메시·재질, 몬스터/시체 풀은 계속 재사용한다.
- 시야 오버레이의 실행 순서를 카메라와 스프라이트 표시 뒤로 옮겼다. 이전 순서에서는 카메라 이동 전 위치로 시야를 계산할 수 있었다.
- 던전 메시 생성의 바닥 칸마다 만들던 4방향 배열을 공유 배열로 바꿨다.

## 지도 및 제작 툴

- 미니맵과 상호작용 안내는 입력 컨트롤이 없는 표시이므로 Repaint에서만 조회·그린다. 가방 등 입력 처리는 기존 이벤트 경로를 유지한다.
- 미니맵의 은신처 표식은 바닥 칸마다 목록을 검색하지 않고 목록을 한 번 순회해 덧그린다. 층 변경 시 무효화해야 하는 도면 캐시는 추가하지 않았다.
- 제작 창의 지도는 스크롤 영역에서 보이는 칸만 Repaint 때 그린다. 도면 전체 영역은 유지하므로 기존 확대·스크롤·브러시 좌표를 사용한다. 입력 처리는 별도로 수행하며 스크롤 영역은 `finally`에서 닫는다.
- 제작 창의 은신처 조회는 재사용 HashSet을 매번 현재 도면으로 채워 Undo·층 변경·미리보기에 대응한다. 브러시 이름 배열도 공유한다.
- 직접 생성한 `SerializedObject`는 사용 후 해제한다. 도면 크기·타일 배열이 누락되거나 맞지 않으면 편집을 진행하기 전에 안내한다. 연결되지 않은 방 등 제작 중 발생할 수 있는 일반 검증 오류는 기존 검증 버튼으로 확인한다.

## 자동 생성

은신처 후보의 주변 벽 점수는 한 번 계산하고, 최소 이격 거리는 새로 선택한 은신처 하나와 비교해 갱신한다. 후보 수 F, 배치 수 H에 대해 기존의 누적 거리 비교 O(F×H²)를 O(F×H)로 줄인다. 후보 순서·동점 선택·난수 호출 순서를 유지하며 생성 버전은 2로 유지한다.

## 검증 및 확인 범위

Unity 6000.6.0f1의 별도 `.utmp/UnityValidation` 프로젝트에서 컴파일과 `OptimizationEditorChecks.RunStandalone`을 실행했다. 종료 코드 0이며 C# 컴파일 오류·경고, 검사 예외는 기록되지 않았다.

데이터 검사 **361개 통과**:

- 4×4, 4×64, 64×4, 20×12, 32×20, 64×64 크기
- 시드 -5~4, 각 2개 층, 은신처 요청 수 0/2/16
- 최적화 이전 기준 구현과 은신처 위치·순서 및 이후 난수 상태 비교, 도면 유효성 검사: 360개
- 카메라 → 스프라이트 → 상태 표시/시야 오버레이의 코드 실행 순서 검사: 1개

재실행용 검사는 `Tests/OptimizationEditorChecks.cs`에 두고 기존 검증 스크립트에도 연결했다. 이번에는 전체 플레이 검사 스크립트를 실행하지 않았다. 사용자 요청대로 플레이 테스트와 Windows 플레이어 실행은 하지 않았으므로 움직임·화면·제작 창 조작의 최종 확인은 아래 항목을 직접 수행해야 한다.

1. 장애물이 있는 곳에서 대각선 추격 → 시야 이탈 → 마지막 목격 위치까지 이동 → 순찰 복귀, 느낌표/물음표 전환.
2. 은신 성공·발각, 은신 종료 후 재발견, 층 이동과 재입장 후 표시/그림자 초기화.
3. 이동·대시 때 시야의 중심과 플레이어 표시가 맞는지, 기존 벽 겹침이 다시 생기지 않는지 확인.
4. `[`, `]`로 미니맵 내부 확대·축소, 탐색 칸·계단·은신처 표식 및 층 전환 확인.
5. 제작 툴에서 64×64 지도의 양 끝까지 스크롤, 확대·축소, 브러시 드래그, Undo, 층 변경과 자동 생성 미리보기 확인.
6. 수동 저장·이어하기와 층 왕복 후 체력·전리품·몬스터 상태 유지 확인.

FPS, CPU 시간, GC.Alloc의 개선 수치는 측정하지 않았다. 실제 콘텐츠 규모에서의 수치는 기존 프로파일링 도구로 별도 측정해야 한다.

## 유지한 내용

저장 형식·암호화·자동 저장 정책과 실제 저장 파일, 씬·프리팹·카탈로그·기존 던전 도면은 변경하지 않았다. 씬 참조가 남은 호환 코드와 설정으로 선택 가능한 3D 경로도 유지한다. 불명확한 참조를 근거로 파일을 삭제하지 않았다.

`Assets/MidtermProfiling/`과 관련 `.meta`·`.asmdef`, 활성화 조건, `.utmp/MidtermProfiling/` 및 `ProfilerCaptures/`의 기존 결과는 수정·삭제하지 않았다.
